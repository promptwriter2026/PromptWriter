# Project Status

## Goals
Build a modular Python desktop application with a CustomTkinter interface that expands rough ideas into detailed English text-to-image prompts using selectable LLM providers and model-specific system instructions.

## Architecture
- `main.py`: Entry point; runs startup initialization and launches the app.
- `promptwriter/config.py`: Application paths, engine constants, and defaults.
- `promptwriter/storage/`: JSON config/app-file seeding and the SQLite history layer.
- `promptwriter/services/`: LLM client, LM Studio API, model catalog, LoRA rules, prompt assembly, image preparation, GPU VRAM monitoring, and ComfyUI/Forge Neo VRAM cleanup.
- `promptwriter/ui/`: CustomTkinter app split into tab/view mixins plus shared tooltip/text-action helpers.
- `config.json`: API keys and selected LLM engine.
- `system_prompts/`: Model-specific instructions, loaded from `.txt` files.
- `data/cameras.json`: Camera and lens choices.
- `data/lora_profiles.json`: Character/LoRA profiles.
- `data/model_profiles.json`: Per-model sampling/context profiles (ignored user runtime data).
- `data/history.db`: Generated prompt history in SQLite.

## Model Profile Preload Fix (v2.2.1)
- Fixed explicit `context_length` never reaching the generation workers: `profile_request_kwargs()` intentionally excludes context (it is not a chat-request field), so `generation_settings.get("context_length")` was always `None` and `ensure_model_loaded()` was skipped, letting LM Studio JIT-load with its default 8192. Added `profile_context_length(engine, profile)` and wired both Generator and Image to Prompt to store it in `generation_settings`; verified the live worker receives 4096.
- Corrected the native load payload to `{"model": <identifier>, "context_length": <int>}`. Live probes against LM Studio 0.4 confirmed `model` is required (`model_key` returns HTTP 400 "Missing required field 'model'"), and unload requires `instance_id`. The earlier `model_key` payload would have failed once the preload trigger fired.
- Context-aware preload: `GET /api/v1/models` loaded instances expose `config.context_length`. If a loaded instance already matches the requested context, no reload happens; if the context differs, only that model's instances are unloaded and the model is reloaded with the requested context. Missing/unreadable instance config is treated as a mismatch. `Auto` leaves existing instances and JIT behavior untouched, and the model-not-found case raises a clear error.
- Load/unload HTTP errors propagate to the generation worker's error handler instead of being swallowed.
- Gemma 4 reasoning: `strip_think_tags()` now also removes `<|channel>thought ... <channel|>` blocks, including unclosed blocks and multiple occurrences, case-insensitively.

## Tab-Switch Freeze Fix (v2.4.2)
- Symptom: switching tabs (especially away from History with a populated list) intermittently froze the window for 3.5–4.2 s and could trigger Windows "Not Responding". Profiling with `time.perf_counter()` measured the following over ~45 tab switches plus one refresh/selection: `ToolTip._hide` was invoked **1,124,984** times (all `<Unmap>`); the main window's `<Unmap>` and `<FocusOut>` binding scripts held **271** separate tooltip callbacks — 27,912 characters of Tcl on a single binding tag; `_position_vram_label` ran **1,965** times for 1.15 s total (max 0.27 s per call); `_refresh_history` took 2.6 s and `_select_history` 0.64 s.
- Root cause 1 (the freeze): every `ToolTip` registered its own `<FocusOut>`/`<Unmap>` handler on the toplevel. Tk bubbles child events to the toplevel binding tag, so unmapping the ~2,000 widgets of the 200-row History tab ran 271 Python callbacks per unmapped widget — millions of `_hide` calls and repeated parsing of a 27 KB Tcl script. Fix: dismiss handlers are now registered **once per toplevel** (tracked in a `weakref.WeakSet`) and only iterate tooltips that are actually visible (`_SHOWN_TOOLTIPS`); `_hide` also returns immediately when there is no timer and no open window. Measured after the fix: `_hide` ~3,000 calls, toplevel binding script 117 characters.
- Root cause 2: `_position_vram_label` was bound to the main window's `<Configure>`, which also receives bubbled child Configure events, and called `update_idletasks()` inside the handler — re-entrant event pumping that amplified every layout change. It now ignores bubbled events (`event.widget is not self`), no longer forces idle tasks, and skips when the computed vertical center is unchanged. Measured after: 847 calls in 0.001 s total.
- Root cause 3 (list churn): `_refresh_history` destroyed and recreated up to 200 `CTkButton` + `ToolTip` pairs, and `_select_history` rebuilt the whole list just to move the highlight. The list now uses a widget pool: rows are created once and reused across refreshes, only changed text is reconfigured, tooltip text is updated in place, unused rows are `pack_forget()`-ed, and selection changes restyle only the affected rows. Search input is debounced (200 ms) so typing does not rebuild the list per keystroke. Measured after: refresh 0.003 s, selection 0.011 s, worst tab switch 0.054 s with 200 rows loaded.
- Regression coverage: added two tests (now 79 total) asserting the toplevel `<Unmap>`/`<FocusOut>` scripts do not grow as tooltips are added and that `_hide` is a no-op without an open window. GUI smoke verified pooled-row identity, selection highlight/reset, empty-state filtering, debounced search scheduling, and repeated History↔Generator switches; a screenshot confirmed the selected-row style still renders correctly.
